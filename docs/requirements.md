# 要件定義書：国家公務員給与計算シミュレーター

> 本書は実装完了後に作成した要件定義書です。既存実装（2026年7月時点）の仕様を
> 正として記述し、今後の変更・拡張の基準として用います。

## 1. 概要

### 1.1 目的

国家公務員（一般職）の給与制度への理解を助けるため、俸給表・各種手当・賞与・
超過勤務手当から月給および年収の**概算**を算出するWebサイトを提供する。

### 1.2 想定利用者

- 国家公務員志望者・就職活動中の学生（給与水準の把握）
- 現職の国家公務員（自身の給与のシミュレーション）
- 給与制度に関心のある一般ユーザー

### 1.3 非対象

- 実際の給与明細の再現や、税務・労務上の正式な計算根拠としての利用
- 地方公務員・独立行政法人職員等、国家公務員（一般職）以外の給与計算

## 2. システム方式

| 項目 | 内容 |
|---|---|
| 種別 | 静的Webサイト（クライアントサイドのみ、サーバーサイド処理なし） |
| 実装技術 | HTML / CSS / バニラJavaScript（ビルド不要、フレームワーク不使用） |
| データ配信 | `data/salary-tables.json` を `fetch` で読み込み（`file://` 実行時は組み込みの参考値にフォールバック） |
| 想定ホスティング | 静的ホスティング（GitHub Pages等）。ローカル確認は簡易HTTPサーバー経由 |
| 対応ブラウザ | `fetch` / `Intl.NumberFormat` 等のモダンAPIが使える最近のブラウザ |
| レスポンシブ対応 | あり（760px以下でフォーム・結果を縦積みに切り替え） |
| コード構成 | `js/data.js`（データ）・`js/calculator.js`（DOM非依存の計算ロジック）・`js/form-controls.js`（index.html/new-hire.html共通のフォーム制御・表示ロジック）・`js/app.js`/`js/new-hire.js`（各ページ固有のDOM配線）に分割 |

## 3. 機能要件

### 3.1 俸給表選択・俸給月額の算出

- 俸給表（俸給の種類）をプルダウンで選択できる。対象は以下20表：
  行政職俸給表(一)(二)、専門行政職、税務職、公安職俸給表(一)(二)、海事職俸給表(一)(二)、
  教育職俸給表(一)(二)、研究職、医療職俸給表(一)(二)(三)、福祉職、専門スタッフ職、
  指定職、任期付研究員俸給表（第一号・第二号）、特定任期付職員俸給表。
- 俸給表には「級構成（`graded`）」と「級のないフラット構成（`flat`）」の2種類があり、
  `flat`型（指定職・任期付研究員等）を選んだ場合は「職務の級」入力欄を自動的に非表示にする。
- `graded`型は「職務の級」→「号俸」の順にプルダウンを連動させ、選択した級・号俸に対応する
  俸給月額（円）を取得する。号俸の選択肢数は俸給表・級ごとに異なる実データに追従する。

### 3.2 地域手当

- 勤務地の級地区分（1級地20%／2級地16%／3級地12%／4級地8%／5級地4%／非支給地0%）を
  プルダウンで選択する。
- 地域手当額 = 俸給月額 × 選択した率（小数点以下切り捨て）。
- プルダウンの下に、級地区分ごとの支給割合を一覧できる折りたたみ表（`<details>`）を設置。
  既定では閉じており、クリックで開閉する。データは`REGIONAL_ALLOWANCE_RATES`
  （プルダウンと共通）から描画するため、率の追加・変更をした場合は自動的に反映される。

### 3.3 扶養手当

- 令和8年4月現在の額のみを対象とする（年度別の切替はしない）。配偶者に係る手当は
  令和8年度時点で廃止済みのため、本ツールでは扱わない。
- 子は「15歳以下」と「16歳以上22歳以下」で額が異なり、後者には加算がある
  （出典: 人事院「国家公務員の諸手当の概要」令和8年4月現在）。
  - 子（15歳以下）: 13,000円
  - 子（16歳以上22歳以下）: 18,000円（基本額13,000円+加算5,000円）
  - 父母等: 6,500円（年度別の正式額は未確認のため一律値）
- 入力: 扶養する子の数（15歳以下）、扶養する子の数（16歳以上22歳以下）、扶養する父母等の数。
  各項目は数値の直接入力ではなく、「−」「＋」ボタンによるボタン選択式（0未満にはならない）。
- 扶養手当額 = 子（15歳以下）の手当額×人数 + 子（16歳以上22歳以下）の手当額×人数 + 父母等の手当額×人数。

### 3.4 住居手当

- 家賃額からの自動計算はしない。支給がある場合のみ、利用者が月額を直接入力する
  （既定値は0円）。入力値がそのまま `housingAllowance` として月額支給額に算入される。
- 通勤手当は本ツールの対象外（非対応）。

### 3.5 本府省業務調整手当（本省手当）

- 本府省（霞が関）勤務の職員に支給される手当（出典: 給与法10条の3、人事院規則9-123）。
  正確な最新額を断定できないため、住居手当と同様に支給がある場合のみ利用者が月額を
  直接入力する（既定値は0円）。入力値がそのまま `honshoAllowance` として月額支給額に
  算入されるが、超過勤務手当の算定基礎（時間単価）にも期末・勤勉手当の算定基礎額にも
  含めない簡略化とする。
- 入力欄の下に、級別の参考額（1級7,200円〜7級以上41,800円）を一覧できる折りたたみ表を
  設置する。複数のWeb記事で一致した値を集約した参考値（出典の確度: 中）であり、
  令和8年度人事院勧告による増額改定（課長補佐級+10,000円・係長級以下+2,000円、
  幹部・管理職員への新規適用51,800円等）は反映されていない旨を明記する（PBI-035参照）。

### 3.6 期末・勤勉手当（賞与）

- 期末手当と勤勉手当を分けて計算し、それぞれ6月期・12月期の額を表示する
  （出典: 人事院「国家公務員の諸手当の概要」令和8年度）。
- 算定基礎額（`bonusBase`） = 俸給月額 + 地域手当（簡略化。実際は役職段階別加算額・
  管理職加算額・専門スタッフ職調整手当等の算入があるが本ツールでは考慮しない）。
- 入力: 期末手当の年間支給月数（既定値2.45か月）、勤勉手当の年間支給月数（成績率適用前、
  既定値2.45か月）、職員区分・勤務成績区分（6月期用・12月期用をそれぞれ独立して設定）。
  人事評価は6月期・12月期で別々に行われるため、同一人物でも期によって成績区分が
  異なりうることを反映している。
- 期末手当（6月期/12月期） = 算定基礎額 × (年間支給月数 ÷ 2)（成績率は適用しない、
  小数点以下切り捨て）。期の職員区分・成績区分設定の影響を受けない。
- 勤勉手当（6月期） = 算定基礎額 × (年間支給月数 ÷ 2) × 6月期の成績率（小数点以下切り捨て）。
  勤勉手当（12月期） = 算定基礎額 × (年間支給月数 ÷ 2) × 12月期の成績率（小数点以下切り捨て）。
- 職員区分（一般職員／特定管理職員（本府省課長等）／指定職職員）ごとに成績率テーブルが異なる。
  指定職職員には「特に優秀」の区分が存在しない（選択肢から除外）。
- 勤務成績区分（特に優秀／優秀／良好／良好でない）に応じた成績率（令和8年度。テーブル自体は
  6月期・12月期で共通だが、どの区分を適用するかは期ごとに独立して選択できる）:

  | 成績区分 | 一般職員 | 特定管理職員（本府省課長等） | 指定職職員 |
  |---|---|---|---|
  | 特に優秀 | 125.25/100以上（下限採用） | 149.25/100以上（下限採用） | 該当なし |
  | 優秀 | 113.75/100以上125.25/100未満（下限採用） | 134.75/100以上149.25/100未満（下限採用） | 115/100以上215/100以下（下限採用） |
  | 良好 | 102.25/100 | 122.25/100 | 101.5/100（事務次官等は107.5/100） |
  | 良好でない | 93.75/100以下 | 112.75/100以下 | 93/100以下 |

  成績率に幅がある区分（特に優秀・優秀）は、ユーザー指示により下限値を採用している。
- 賞与年間合計 = 6月期（期末+勤勉） + 12月期（期末+勤勉）。

### 3.7 超過勤務手当（残業代）

- 時間単価 = (俸給月額 + 地域手当 + 扶養手当) × 12か月 ÷ 年間所定勤務時間。
  年間所定勤務時間 = 週38時間45分 × 52週 = 2,015時間。住居手当・本省手当は算定基礎に
  含めない（住居手当は実費補填的な性格のため、本省手当は算定基礎への算入可否を
  確認できていないための簡略化）。
- 入力: 平日時間外勤務時間（深夜を除く月間合計）、うち深夜(22時〜翌5時)の時間外勤務時間、
  休日勤務時間（深夜を除く月間合計）、うち深夜の休日勤務時間。
- 割増率:

  | 区分 | 月60時間以下 | 月60時間超 |
  |---|---|---|
  | 平日時間外（22時まで） | 125% | 150% |
  | 平日時間外・深夜（22時〜翌5時） | 150% | 175% |
  | 休日勤務（22時まで） | 135% | （60時間判定の対象外、常に135%） |
  | 休日勤務・深夜 | 160% | （60時間判定の対象外、常に160%） |

- 月60時間の判定対象は「休日勤務を除く時間外勤務時間（深夜を含む）」の合計。60時間を
  超えた分は、平日の通常時間から優先的に充当し、それでも不足する場合は深夜時間に充当する
  （実際の勤務順序までは特定できないための簡便な割当てであることを画面上に明記する）。
- 60時間を超えている場合、結果画面にその旨の注記を表示する。

### 3.8 計算結果表示

以下を一覧表示する（すべて円単位、`Intl.NumberFormat` によるフォーマット）。

1. 俸給月額
2. 地域手当
3. 扶養手当
4. 住居手当
5. 本省手当
6. 月額支給額 合計（残業代除く）＝ 1〜5の合計
7. 時間外勤務の時間単価
8. 超過勤務手当
9. 月額支給額 合計（残業代込み）＝ 6 + 8
10. 期末手当（6月期）／勤勉手当（6月期）
11. 期末手当（12月期）／勤勉手当（12月期）
12. 賞与（年間合計）＝ 10 + 11
13. 年収 概算 ＝ 9 × 12 + 12（毎月同じ超過勤務が続くと仮定した概算）

入力変更時はページ遷移・送信なしにリアルタイムで再計算・再描画する。

### 3.9 データ読み込みと表示

- 起動時に `data/salary-tables.json` を非同期で読み込み、成功すれば実データ（20表）を、
  失敗すれば行政職俸給表(一)相当の参考値にフォールバックする。
- 読み込み結果（実データか参考値か、データの適用時点）を画面上部の注記に表示する。

### 3.10 俸給表バージョン切替

- 画面上部に「俸給表のバージョン」選択欄を設け、`data/vintages.json` に列挙された
  バージョン（例: 現行／人事院勧告後）を切り替えられる。
- 各バージョンは `{ key, label, file, effectiveDate, available }` を持ち、`file` が
  `null`／`available: false` のバージョンは選択肢を無効化し、選ぼうとしても現行データに
  留まる（データ未登録の旨を注記表示）。
- バージョンを切り替えると、俸給表選択・級・号俸のプルダウンと生涯賃金シミュレーションの
  状態を再取得したデータに合わせてリセットする。
- 2026年7月時点では `current`（現行、2026-04-01施行）のみデータが登録されており、
  `post_recommendation`（人事院勧告後）は未登録（PBI-013として保留中）。

### 3.11 生涯賃金シミュレーション

- 1〜35年目までの「級」「号俸」「地域手当区分」を年ごとに設定できる一覧表を、メイン画面の
  計算結果の下に表示する。俸給表・扶養手当・住居手当・賞与支給月数・成績区分・超過勤務の
  設定はメインフォームの値を全期間共通で使用する。
- 「自動生成する」ボタンで、指定した年数・1年目の号俸・毎年の昇給号俸数（4/6/8号俸から選択）
  をもとに、1年目はメインフォームの選択値を引き継ぎ、2年目以降は級・地域手当区分を変えずに
  号俸のみ積み上げた初期状態を生成する（号俸は俸給表・級ごとの上限でクリップされる）。
- 生成後、各年の行（級・号俸・地域手当区分）は個別に編集でき、昇格・転勤のシミュレーションに
  対応する。
- メインフォームの入力（扶養手当・住居手当・賞与支給月数・成績区分・超過勤務等）を変更すると、
  生涯賃金シミュレーションの各年の年収・合計も自動的に再計算される。
- 俸給表（適用俸給表またはバージョン）を変更すると、級構成の互換性が失われるためシミュレーション
  状態はリセットされる。
- 表示: 各年の年収概算、生涯賃金合計、年収の平均、最終年の年収。

### 3.12 新規採用職員向け別ページ（new-hire.html）

- `js/data.js` / `js/calculator.js` を共有する専用ページ。初任給（俸給表・級・号俸・地域手当・
  扶養手当・住居手当）と、採用初年度の1回目・2回目の賞与、初年度年収概算を計算する。
- 初期値は新規採用者の典型例（俸給表=行政職俸給表(一)、1級1号俸、扶養家族なし）を設定する。
- index.htmlとは異なり、期末・勤勉手当を区別せず「年間支給月数（満額の場合）」1本で扱い、
  成績率は適用しない（新規採用者向けの簡略版）。基準日（6月1日・12月1日）までの在職期間に
  応じて支給割合（期間率）が下がる制度を反映し、1回目・2回目それぞれに在職期間別割合
  （6か月100%／5か月以上6か月未満80%／3か月以上5か月未満60%／3か月未満30%）を選択できる。
  既定値は1回目「3か月未満（30%）」、2回目「6か月（100%）」（4月採用を想定した典型例）。
- 賞与額 = 算定基礎額（俸給+地域手当）× (年間支給月数 ÷ 2) × 在職期間別割合（小数点以下切り捨て）。
- 超過勤務手当は対象外（新規採用者は時間外勤務が少ない前提のため非表示）。
- メインページ・本ページ相互にリンクを設置する。

### 3.13 入力内容の保存・復元

- index.html・new-hire.htmlそれぞれで、フォーム（`#calc-form`）内のid付きinput/select
  すべての値を、変更のたびに`localStorage`へページ別のキー（`salary-calculator:index` /
  `salary-calculator:new-hire`）で自動保存する。サーバーへは送信しない。
- 次回アクセス時、ページ読み込み時に保存済みの値があれば自動的に復元し、続きから
  計算できるようにする。俸給表・級・号俸・成績区分（index.htmlのみ）など、他の項目の
  選択肢に影響する項目は、選択肢を再構成した後に復元する（例: 俸給表を復元してから
  級の選択肢を作り、その中に保存済みの級があれば選択する）。select要素は、保存値が
  現在の選択肢に存在し無効化されていない場合のみ復元する。
- フォーム下部に「保存した入力内容を削除して初期状態に戻す」ボタンを設置し、
  押すと保存データを削除してページを再読み込みする（既定値に戻る）。
- 画面上部の注意書きに、入力内容がこの端末のブラウザ内に保存され、サーバーには
  送信されない旨を明記する。
- `localStorage`が使えない環境（プライベートブラウジング等）では、保存・復元を
  静かに諦め、通常どおり既定値で動作する（エラーにはしない）。

## 4. 非機能要件

- **正確性の限界の明示**: 画面上部に常時、概算シミュレーターであること・控除前の額面
  ベースであることを明記する。
- **オフライン耐性**: `data/salary-tables.json` が取得できない環境でも参考値でアプリが
  機能し続けること（クラッシュしない）。
- **保守性**: 俸給表データは `scripts/extract-salary-tables.py` により元データ（xlsx）
  から再生成可能とする。
- **アクセシビリティ**: 結果パネルに `aria-live="polite"` を付与し、再計算結果が
  スクリーンリーダーに通知されるようにする。
- **パフォーマンス**: ビルドプロセスを持たず、静的ファイルの配信のみで完結すること。
- **テスト容易性**: 計算ロジック（`js/data.js` / `js/calculator.js`）はDOMに依存しない
  純粋関数として実装し、Node上でユニットテストできるようにする。

## 5. データ仕様

### 5.1 `data/salary-tables.json`

```json
{
  "source": "データの出典説明",
  "note": "適用時点・注意事項",
  "effectiveDate": "YYYY-MM-DD",
  "order": ["administrative_1", "..."],
  "tables": {
    "<table_key>": {
      "label": "画面表示用ラベル",
      "type": "graded | flat",
      "grades": { "<級>": [号俸1の俸給月額, 号俸2の俸給月額, ...] },
      "steps": [号俸1の俸給月額, ...]
    }
  }
}
```

- `type: "graded"` は `grades` を、`type: "flat"` は `steps` を持つ。
- 出典: ユーザー提供の公式俸給表データ（一般職の職員の給与に関する法律 別表に基づく）。
  施行日は令和8年4月1日（2026-04-01）。それ以降に人事院勧告等による改定があった場合は
  最新の公表資料との照合が必要。

```json
{
  "note": "...",
  "vintages": [
    { "key": "current", "label": "現行（令和8年4月1日施行）", "file": "salary-tables.json",
      "effectiveDate": "2026-04-01", "available": true },

```

- `file` が `null` または `available: false` のバージョンは選択不可として扱う。

### 5.3 その他の定数データ（`js/data.js` に定義）

- 地域手当率（6区分）
- 扶養手当額（令和8年4月現在。子は15歳以下/16〜22歳の2区分、父母等）
- 本府省業務調整手当（本省手当）の級別参考額（7区分、要確認）
- 超過勤務手当の割増率（6区分）、年間所定勤務時間
- 期末・勤勉手当の在職期間別割合（期間率、4区分、new-hire.html専用）
- 勤勉手当の成績率（職員区分3種 × 成績区分4区分、令和8年度）

### 6.3 デザインシステム（`css/style.css`）

- 色・影・角丸・間隔をCSSカスタムプロパティ（`:root`）で一元管理し、両画面で統一感を
  持たせている。配色は青系の主色（`--color-primary`）と、合計金額を目立たせる緑系の
  アクセント（`--color-accent`）の2色を軸に構成。
- 特定サイトの見た目をそのまま複製するのではなく、政府系デザインシステム（GOV.UK、
  デジタル庁デザインシステム等）の明快な情報設計と、家計・給与計算系のSaaS/家計簿
  アプリに見られる「カード型の陰影」「合計金額を大きく強調するヒーロー表示」
  「滑らかなホバー/フォーカスの操作感」という複数の潮流を参考に、独自の配色・
  構成で組み立てている。
- 計算結果パネルの先頭に、年収概算を大きく強調する`result-hero`（グラデーション背景
  ＋大きな数字）を設置し、詳細な内訳は控えめな小見出し（`内訳`）の下に一覧表示する
  ことで、「まず結果の要点が伝わる」画面構成にしている。
- フォーム部品（select・input・カウンターボタン・号俸ボタン）は角丸・枠線・
  ホバー/フォーカス時の色変化を統一。selectは矢印アイコンをインラインSVG（データURI）
  で描画し、外部リソースへの通信なしで見た目を統一している。
- favicon（円マークのインラインSVG）とmeta descriptionを追加し、ブラウザタブでの
  識別性・検索エンジンでの表示を改善した。

## 7. 用語集

| 用語 | 説明 |
|---|---|
| 俸給 | 基本給に相当する部分。俸給表の「職務の級」と「号俸」で決まる |
| 号俸 | 同じ級の中での細かい昇給ステップ |
| 地域手当 | 民間賃金の地域差を反映するための手当。勤務地の級地区分で率が決まる |
| 本省手当 | 本府省業務調整手当の通称。本府省（霞が関）勤務の職員に支給される手当 |
| 期末手当・勤勉手当 | 賞与に相当する手当。合わせて「ボーナス」と通称される |
| 成績率 | 勤勉手当の額を左右する、人事評価結果に基づく倍率。職員区分・成績区分ごとに異なる |
| 超過勤務手当 | 時間外勤務に対する残業代に相当する手当 |
| 期間率 | 期末・勤勉手当の基準日までの在職期間に応じた支給割合。在職期間が短いほど小さくなる |
| 俸給表のバージョン | 人事院勧告等による改定前後など、適用時点が異なる俸給表データの区別 |

## 8. 既知の制約・今後の課題

- 期末・勤勉手当の算定基礎額は「俸給+地域手当」に簡略化しており、実際に一部算入される
  扶養手当・役職段階別加算額・管理職加算額・専門スタッフ職調整手当・本省手当等は
  考慮していない。
- 超過勤務手当の算定基礎額は「俸給+地域手当+扶養手当」のみを対象とし、広域異動手当・
  研究員調整手当・専門スタッフ職調整手当・本省手当等、対象となりうる他の手当は未実装。
- 本省手当（本府省業務調整手当）は正確な最新額を断定できないため、利用者が実際の支給額を
  直接入力する方式とし、参考として示す級別金額（1級7,200円〜7級以上41,800円）は
  Web検索で確認できた値の集約（出典の確度: 中）。令和8年度人事院勧告による増額改定・
  幹部職員への新規適用（PBI-035）は反映していない。
- 扶養手当のうち父母等の額（6,500円）は正式な出典未確認。子の「16歳以上22歳以下」区分の
  加算額（5,000円）も、人事院公表の「諸手当の概要」PDFに基づく値で法令原文とは未突合。
- 地域手当の「勤務地→級地区分」の市区町村マッピングは実装しておらず、利用者が自身の
  級地区分を直接選択する方式としている（東京都特別区が1級地であることのみ確認済み）。
- 通勤手当・所得税・住民税・共済組合掛金（社会保険料相当）、単身赴任手当、寒冷地手当等は非対応。
- 住居手当は家賃額からの自動計算をせず、利用者が支給額を直接入力する方式のため、
  実際の家賃と支給額の関係（人事院規則9-42の計算式）は本ツールでは扱わない。
- 年収概算は「毎月同じ超過勤務時間が続く」という仮定に基づく単純な12倍であり、月ごとの
  繁閑は考慮していない。
- 期末・勤勉手当の在職期間別割合（期間率、6か月100%／5か月以上80%／3か月以上60%／
  3か月未満30%、new-hire.htmlで使用）はWeb検索で確認できた一般的な区分であり、
  人事院規則9-83の原文とは未突合（要確認）。index.htmlの期末・勤勉手当は期間率を
  考慮していない（通年在籍を前提とした概算）。
- 勤勉手当の成績率テーブル（令和8年度）はユーザー提供の情報に基づくが、原典の法令・
  規則番号は未特定。「特に優秀」「優秀」の階級幅は下限値を採用しており、実際に支給され
  うる上限までは反映していない。
- 生涯賃金シミュレーションの2年目以降の自動生成は「級・地域手当区分を変えず号俸のみ積み上げ」
  という単純化であり、実際に発生する昇格・転勤・異動は反映されない（手動編集での対応が前提）。
  また各年の成績区分は全期間共通の設定を使うため、年ごとの評価変動は反映されない。
- 「人事院勧告後」の俸給表バージョンはデータ未登録（PBI-013）。ネットワークポリシーにより
  e-Gov法令API・人事院サイトへの直接アクセスがブロックされているため、ユーザーからのデータ
  提供が必要。
