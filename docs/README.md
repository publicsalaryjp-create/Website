# ドキュメント一覧

このプロジェクトのドキュメントの案内図です。初めての方は上から順に読むのがおすすめです。

| ドキュメント | 何のためのものか | いつ見る／更新する |
|---|---|---|
| [requirements.md](requirements.md) | 要件定義書。今アプリが何をするか（機能・計算式・データ仕様）の正式な記録 | 機能を追加・変更したとき |
| [product-backlog.md](product-backlog.md) | プロダクトバックログ。やりたいこと・直したいことの一覧と優先順位 | やりたいことを思いついたとき、着手・完了したとき |
| [definition-of-done.md](definition-of-done.md) | 開発体制の説明と、「着手してよい条件」「完了と言える条件」の基準 | スプリントを始める前・終わったとき |
| [sprint-template.md](sprint-template.md) | スプリント（作業の区切り）の記録テンプレートと書き方 | 新しいスプリントを始めるとき |
| [sprints/](sprints/) | 過去のスプリント記録（実例） | 記録の書き方を確認したいとき |
| [../CHANGELOG.md](../CHANGELOG.md) | 利用者向けの変更履歴 | 変更をリリースしたとき |

## そもそも「アジャイル開発」とは

決まった仕様を一度に全部作りきるのではなく、

1. やりたいことを**プロダクトバックログ**に書き出し
2. 優先順位の高いものから小さく区切って（**スプリント**）
3. 作って→動かして確認して（**Definition of Done**）
4. ふりかえって次に活かす

というサイクルを繰り返す進め方です。給与計算のように「正確さ」が重要なテーマでは、
一度に完璧を目指すよりも、小さく作って都度、監修者に確認してもらう方が
間違いに早く気づけるという利点があります。

## このプロジェクトでの回し方（要約）

1. `product-backlog.md` から次にやることを選ぶ（なければ新しく追加する）
2. `definition-of-done.md` の Definition of Ready を確認してから着手する
3. `sprint-template.md` をコピーして `sprints/sprint-XX.md` を作り、計画を書く
4. 実装する（給与制度に関わる変更は、後で監修者に確認してもらうことを前提に進めてよい）
5. `definition-of-done.md` の Definition of Done を満たしたら完了とする
6. `CHANGELOG.md` に変更を記録する
7. スプリント記録に「ふりかえり」を書き、次のバックログに反映する
