# スプリントとは・テンプレートの使い方

## スプリントとは

一定の期間（1〜2週間くらいが目安。一人開発なら「区切りの良い作業のまとまり」でも構いません）を
区切って、その期間で「何をやるか」を決め（スプリント計画）、実際に作業し、
終わったら「どうだったか」を振り返る（ふりかえり）——このサイクルをスプリントと呼びます。

一気に全部を作ろうとせず、小さく区切って「計画→実施→ふりかえり」を繰り返すことで、
- 今どこまで進んでいるかが分かりやすくなる
- 途中で優先順位を見直しやすくなる
- 同じ失敗を繰り返しにくくなる

というメリットがあります。

## 使い方

1. 新しいスプリントを始めるときは、このファイルの下にある「テンプレート本体」をコピーして
   `docs/sprints/sprint-XX.md`（XXは連番、例: `sprint-05.md`）として保存する。
2. 「スプリント計画」を、`docs/product-backlog.md` から選んだ項目を使って埋める。
3. 作業中は「実施内容」に簡単なメモを残す（日記のようなもので構いません）。
4. スプリントが終わったら「ふりかえり」をKPT形式で埋める。
   - **Keep（続けたいこと）**: うまくいったこと、今後も続けたいやり方
   - **Problem（困ったこと）**: うまくいかなかったこと、時間がかかった原因
   - **Try（次にやってみること）**: Problemを踏まえて次に試したいこと
5. ふりかえりで出てきた改善点は、必要であれば `docs/product-backlog.md` に新しい項目として追加する。

過去の実例は `docs/sprints/sprint-01.md` 〜 `sprint-04.md` にあります
（このプロジェクトのこれまでの開発を、事後的にスプリント形式で整理したものです）。
初めて書くときはそちらを参考にしてください。

---

## テンプレート本体（コピーして使ってください）

```markdown
# スプリント XX（YYYY-MM-DD 〜 YYYY-MM-DD）

## スプリント計画

- 目標（このスプリントで達成したいこと）:
- 取り組むバックログ項目:
  - PBI-XXX: （タイトル）

## 実施内容

- YYYY-MM-DD: （やったこと）

## ふりかえり（KPT）

- Keep:
- Problem:
- Try:

## 次回への申し送り

- （バックログに追加した項目があれば記載）
```
